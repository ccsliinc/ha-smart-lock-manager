# Smart Lock Manager Frontend

The Smart Lock Manager sidebar panel is a single vanilla custom element
(`<smart-lock-manager-panel>`). This directory holds its source (`src/`), the
esbuild build tooling, and the built bundle (`dist/`) that Home Assistant loads.

There is no framework and no runtime dependency. The build only bundles the
`src/` ES modules into one self-registering IIFE.

## Layout

```
frontend/
├── package.json      # esbuild + eslint devDeps, build/lint scripts
├── package-lock.json # committed lockfile
├── .eslintrc.js      # self-contained ESLint config (no shareable config)
├── src/
│   ├── main.js               # the SmartLockManagerPanel class + registration
│   ├── styles.js             # panelStyles(self): the panel <style> block
│   ├── constants.js          # ZS_DAYS, CUSTOM_CARD_META
│   └── utils/
│       ├── format.js         # escHtml, fmtTime, formatAccessLogTime, untilMorningHours
│       └── presentation.js   # slotDisplayInfo, accessLogPresentation,
│                             #   devAlertPresentation, zoneSlotDisplay
└── dist/
    └── smart-lock-manager-panel.js   # BUILD OUTPUT (committed, git-tracked)
```

`src/main.js` is the entry point and holds the bulk of the component (render,
modals, service calls, event handling). The extracted modules are the pure,
instance-state-free helpers and the stylesheet; the class delegates to them so
every original method, call site and behavior is preserved.

## Build

```bash
npm install       # installs esbuild + eslint into node_modules/ (gitignored)
npm run build     # bundles src/main.js -> dist/smart-lock-manager-panel.js
npm run lint      # eslint over src/
```

The build command is:

```
esbuild src/main.js --bundle --outfile=dist/smart-lock-manager-panel.js --format=iife
```

- **`--format=iife`** — the panel is loaded as a plain `<script>` at the
  custom-panel `js_url` (see `panel.py`), so the output must self-register the
  element on load, not be an ES module the browser has to `import`. The IIFE
  wraps the redefinition guard, the class, `customElements.define(...)`, and the
  `window.customCards` registration exactly as the original single file did.
- **Not minified** — the committed `dist` stays readable and diffable so the
  build output can be reviewed like any other source in the repo.

## dist is the build output

`dist/smart-lock-manager-panel.js` is generated by `npm run build`. It is
committed to the repo (Home Assistant serves it via the static path registered
in `panel.py`), but it is a build artifact: edit `src/`, then rebuild. Do not
hand-edit `dist/`.

This panel manages physical door codes on live locks. When changing `src/`,
rebuild and confirm the built `dist` is behavior-equivalent (same methods,
event handlers, `callService`/`callApi` calls, DOM ids, and the 2026.8.0
security behaviors: reads `has_pin_code` and never a raw `pin_code`, never
round-trips a raw PIN to the browser, keeps an existing code when the PIN field
is left blank on save).
